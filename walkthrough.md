## Key Bug Fixes Applied

### 1. ABI Zero-Padding Bug (Root Cause of "Balance Always 0")
```go
// WRONG — pads with spaces, not zeros
fmt.Sprintf("%064s", clean)

// FIXED
strings.Repeat("0", 64-len(clean)) + clean
```
EVM calldata requires 32-byte zero-padded hex words. Space-padding caused every `eth_call` to return empty data, resulting in `balanceOf()` returning 0.

### 2. Wrong `checkIn(bytes32)` Function Selector
```
Hardcoded: 0xda8c229e  ← wrong
Correct:   0x4662d1dd
```
All function selectors are now computed at runtime using `keccak256Sum`:
```go
sel := "0x" + hex.EncodeToString(keccak256Sum([]byte("checkIn(bytes32)"))[:4])
```

### 3. POI Lookup Blocking Blockchain Transaction
Check-in and review services previously returned `404 POI Not Found` when the POI wasn't in MongoDB (because the app uses static JSON data, not DB-seeded POIs). Both services now log a warning and continue — the blockchain tx fires regardless.

### 4. Community Rating & Federated Model Score Showing 0
The `score` field is only present in `recommendations.json` (written by the FL model), not in `pois.json` (raw venue data). Non-recommended POIs now get a **derived score** computed from normalised check-in count:
```js
const derivedScore = parseFloat(((p.checkins || 0) / maxCheckins).toFixed(3));
```
This gives all 34k POIs meaningful non-zero scores in the Transparency Panel.

## How to Run Everything

> **Prerequisites:** MongoDB running locally on `mongodb://localhost:27017` and Node.js + Go installed.

### Step 0 — Pull Latest Code
```bash
git pull origin main
```

---

### Step 1 — Smart Contracts (Terminal A — keep running)
```bash
cd contracts/trustchain-task6-s1
npm install

# Start the local Hardhat blockchain — keep this terminal open
npx hardhat node --port 8545
```

### Step 2 — Deploy Contracts (Terminal B — run once)
```bash
cd contracts/trustchain-task6-s1

# Deploy TrustToken, UserRegistry, StakingContract, ProofOfRecommendation, GeoRecommender
npx hardhat run scripts/deploy.js --network localhost
# → writes deployments/localhost.json (backend reads this automatically)
```

---

### Step 3 — Go Backend (Terminal C — keep running)
```bash
cd backend

# All config is already set in backend/.env — no manual env vars needed
go run ./cmd/server
# → http://localhost:8080  (blockchain=hardhat, recommendations=federated)
```

---

### Step 4 — Frontend (Terminal D — keep running)
```bash
cd frontend
npm run dev
# → http://localhost:5173  (Vite proxy routes /api → localhost:8080)
```

---

### Step 5 — Federated Learning (optional — regenerate recommendations)
```bash
cd federated
python launch_fl.py
# → writes frontend/src/recommendations.json
```

## Transparency Panel — Score Computation

When a user clicks "Why recommended?" on any POI:

| Score | Source | Formula |
|---|---|---|
| **Proximity Score** | Distance to user | `max(0, 110 - distance_degrees × 55)` |
| **Community Rating** | Check-in volume | `(poi.checkins / max_checkins) × 100` |
| **Federated Model Score** | FL output or derived | `poi.score × 100` (real for recommended, derived for others) |

The `allPoisToRender` memo enriches every POI with a `score` field — the FL model score for recommended POIs, or a derived score from check-in normalisation for all others — ensuring no POI ever shows 0/0/0.
